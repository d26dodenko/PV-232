## 1. Анализ исходного модуля

Объект тестирования: функция `calculate_delivery_cost` из модуля `delivery.py`.

Функция рассчитывает стоимость доставки по трем входным параметрам:

| Параметр | Назначение | Допустимые значения | Недопустимые значения |
| --- | --- | --- | --- |
| `order_amount: float` | Сумма заказа | Число `>= 0` | Число `< 0` |
| `distance_km: float` | Расстояние доставки в километрах | Число `>= 0` | Число `< 0` |
| `is_premium: bool` | Признак premium-пользователя | `True`, `False` | Другие значения в задании не описаны |
| Результат `float` | Итоговая стоимость доставки | Неотрицательное число | При некорректных входных данных вместо результата выбрасывается `ValueError` |

Бизнес-правила:

1. Если `order_amount < 0`, выбрасывается `ValueError("order_amount must be >= 0")`.
2. Если `distance_km < 0`, выбрасывается `ValueError("distance_km must be >= 0")`.
3. Если `order_amount >= 5000`, доставка бесплатна и равна `0.0`.
4. Если `order_amount < 5000` и `distance_km <= 5`, доставка стоит `200.0`.
5. Если `order_amount < 5000` и `5 < distance_km <= 20`, доставка стоит `500.0`.
6. Если `order_amount < 5000` и `distance_km > 20`, доставка стоит `500.0 + (distance_km - 20) * 30.0`.
7. Если `is_premium=True`, применяется скидка 50% на рассчитанную стоимость доставки.
8. Если доставка бесплатна, premium-скидка не меняет результат: итог остается `0.0`.

Классы эквивалентности:

| Параметр | Классы |
| --- | --- |
| `order_amount` | отрицательная сумма; сумма от `0` до `4999.99`; сумма `5000` и больше |
| `distance_km` | отрицательное расстояние; `0..5`; больше `5` и до `20`; больше `20` |
| `is_premium` | обычный пользователь; premium-пользователь |

Граничные значения:

- для суммы заказа: `-0.01`, `0`, `4999.99`, `5000`, `5000.01`;
- для расстояния: `-0.01`, `0`, `4.99`, `5`, `5.01`, `19.99`, `20`, `20.01`;
- для premium-статуса: `False`, `True`.

## 4. Покрытые ветви кода

Тесты покрывают следующие ветви функции:

| Условие | Покрытая ветка `True` | Покрытая ветка `False` |
| --- | --- | --- |
| `order_amount < 0` | TC-24, TC-25 | TC-01 - TC-23, TC-26, TC-27 |
| `distance_km < 0` | TC-26, TC-27 | TC-01 - TC-25 |
| `order_amount >= 5000` | TC-15, TC-16, TC-17, TC-18, TC-23 | TC-01 - TC-14, TC-19 - TC-22 |
| `distance_km <= 5` | TC-01 - TC-05, TC-19 | TC-06 - TC-14, TC-20 - TC-22 |
| `distance_km <= 20` | TC-06 - TC-09, TC-14, TC-20 | TC-10 - TC-13, TC-21, TC-22 |
| `is_premium` | TC-19 - TC-23, TC-25, TC-27 | TC-01 - TC-18, TC-24, TC-26 |

Таким образом, проверены:

- позитивные сценарии для каждого тарифа;
- негативные сценарии для некорректной суммы заказа и расстояния;
- граничные значения около `0`, `5`, `20`, `5000`;
- скидка для premium-пользователей;
- бесплатная доставка;
- сочетание premium-статуса и бесплатной доставки.

## 5. Вывод

Тестирование связывает требования с фактическим поведением программы. В этой лабораторной работе тесты показали, что функция корректно обрабатывает основные тарифы, граничные значения, premium-скидку, бесплатную доставку и ошибки входных данных.

В жизненном цикле ПО такие автотесты важны потому, что они помогают быстро находить регрессии после изменений кода, подтверждают выполнение бизнес-правил и повышают доверие к качеству программы. При этом тесты не заменяют требования и проектирование: если важное поведение не описано в задании, его нужно отдельно уточнять и только потом покрывать проверками.
