## 1. Описание тестируемых эндпоинтов

В рамках работы была протестирована коллекция, покрывающая основные CRUD-операции публичного API для бронирования отелей:
- `POST /auth` — авторизация и получение токена.
- `GET /booking` — получение списка всех бронирований.
- `GET /booking/{id}` — получение деталей конкретного бронирования.
- `POST /booking` — создание нового бронирования.
- `PUT /booking/{id}` — полное обновление бронирования (требуется токен).
- `DELETE /booking/{id}` — удаление бронирования (требуется токен).
- `GET /ping` — проверка доступности сервиса (health check).

## 5. Баг-репорты (

### BUG-API-01 — Отсутствие авторизации при PUT и DELETE запросах
- **Заголовок:** PUT и DELETE возвращают `403 Forbidden` из-за отсутствия токена.
- **Шаги воспроизведения:**
  1. Выполнить `POST /auth` и получить токен.
  2. Выполнить `POST /booking` и получить `bookingId`.
  3. Выполнить `PUT /booking/{{bookingId}}` без скрипта сохранения токена или без заголовка `Cookie: token={{token}}`.
- **Ожидаемый результат:** `200 OK` (успешное обновление).
- **Фактический результат:** `403 Forbidden`.
- **Severity:** Major.
- **Priority:** High.
- **Причина:** В Postman не настроены скрипты (вкладка Tests) для динамического сохранения токена в переменную окружения и передачи его в заголовке Cookie.

### BUG-API-02 — Нестандартные коды ответов 
- **Заголовок:** `POST /booking` возвращает 200 вместо 201, `GET /ping` возвращает 201 вместо 200.
- **Шаги воспроизведения:**
  1. Отправить `POST /booking` с валидным JSON.
  2. Отправить `GET /ping`.
- **Ожидаемый результат:** `201 Created` для создания, `200 OK` для пинга.
- **Фактический результат:** `200 OK` для создания, `201 Created` для пинга.
- **Severity:** Minor (учебное API).
- **Priority:** Low.

## 6. Выводы

В ходе лабораторной работы было проведено интеграционное тестирование публичного API Restful-Booker с использованием Postman Collection Runner. 

1. **Успешно проверено:** Работоспособность базовых GET и POST запросов. Цепочка передачи `bookingId` между запросами сработала корректно (запросы к ID 694 прошли успешно).
2. **Выявлены проблемы:** Запросы, требующие авторизации (`PUT`, `DELETE`), вернули `403 Forbidden`. Это связано с тем, что на этапе текущего прогона не были внедрены скрипты автоматизации (вкладка Tests), которые должны извлекать токен из ответа `POST /auth` и подставлять его в Cookie. 
3. **Найдены особенности API:** Подтверждено, что Restful-Booker использует нестандартные коды ответов (200 при создании, 201 при пинге), что иллюстрирует важность ручной проверки и составления таблиц расхождений (Discrepancies), так как реальное поведение API часто отличается от документации и REST-стандартов.

**Дальнейшие шаги:** Для успешного прохождения всей цепочки тестов (включая удаление и получение 404) необходимо добавить JavaScript-скрипты во вкладку Tests для автоматического сохранения `token` и `bookingId` в переменные окружения, а также использовать заголовок `Cookie: token={{token}}` для авторизованных запросов.
