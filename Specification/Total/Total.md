# ЛАБОРАТОРНАЯ РАБОТА

**Дисциплина:** Архитектура, проектирование и ППС

**Тема:** Анализ требований, выбор архитектуры программного обеспечения и организация командной разработки

---

## Цель работы

Получить практические навыки анализа требований к программному обеспечению, проектирования архитектуры информационной системы, формирования команды разработки и распределения задач между участниками проекта.

---

## Выбор проекта

Выберите один проект информационной системы из предложенных вариантов или предложите собственный проект.

**Примеры проектов:**

- Сервис бронирования отелей.
- Интернет-магазин.
- Электронная библиотека.
- Система управления учебными курсами.
- Сервис записи на прием.
- Система управления задачами.
- Сервис доставки еды.
- Система учета студентов и успеваемости.
- Система управления мероприятиями.
- Собственный проект, согласованный с преподавателем.

Выбранный проект должен иметь не менее 5 функциональных требований и предусматривать взаимодействие пользователя с информационной системой.

---

## Порядок выполнения работы

### Задание 1. Описание проекта

Необходимо указать:

1. Название проекта.
2. Назначение системы.
3. Целевую аудиторию.
4. Основные проблемы, которые решает система.
5. Основные функции системы.
6. Предполагаемые условия эксплуатации.

---

### Задание 2. Формирование требований

#### Функциональные требования

Для каждого требования укажите:

- идентификатор;
- название;
- описание;
- пользователя, который выполняет действие;
- ожидаемый результат.

#### Нефункциональные требования

Определите требования к:

- надежности;
- производительности;
- безопасности;
- масштабируемости;
- условиям эксплуатации.

---

### Задание 3. Проектирование архитектуры

Рассмотрите три архитектурные модели для выбранного проекта.

#### 3.1. Монолитная архитектура

Опишите:

- основные компоненты системы;
- принцип взаимодействия компонентов;
- способ хранения данных;
- особенности развертывания;
- преимущества и недостатки выбранного подхода.

Представьте архитектуру в виде схемы.

#### 3.2. Микросервисная архитектура

Разделите систему на независимые сервисы.

Для каждого сервиса укажите:

- название;
- назначение;
- основные функции;
- данные, за которые отвечает сервис;
- способ взаимодействия с другими сервисами.

Представьте архитектуру в виде схемы.

#### 3.3. Многослойная архитектура

Разделите систему на логические слои.

Рассмотрите следующие слои:

- слой представления;
- слой бизнес-логики;
- слой доступа к данным.

Опишите назначение каждого слоя, его основные компоненты и взаимодействие с другими слоями.

Представьте архитектуру в виде схемы.

---

### Задание 4. Составление технического задания

Подготовьте техническое задание на разработку выбранной информационной системы. Техническое задание должно соответствовать структуре ГОСТ 34.602-89 и содержать следующие разделы:

#### 1. Введение

Укажите название системы, ее назначение и краткое описание.

#### 2. Основания для разработки

Укажите основание выполнения проекта, учебное задание и требования заказчика.

#### 3. Назначение и цели создания системы

Опишите назначение системы и цели ее разработки.

#### 4. Требования к системе

Определите:

- функциональные требования;
- требования к надежности;
- требования к производительности;
- требования к безопасности;
- требования к условиям эксплуатации.

#### 5. Состав и содержание работ

Опишите этапы разработки, основные работы и ожидаемые результаты.

#### 6. Порядок контроля и приемки

Определите способы проверки системы, критерии приемки и порядок демонстрации проекта.

#### 7. Требования к составу и содержанию документации

Перечислите документы, которые необходимо подготовить в процессе разработки.

#### 8. Источники разработки

---

### Задание 5. Формирование команды разработки

Определите состав команды, необходимый для разработки выбранного проекта.

В зависимости от размера команды распределите следующие роли:

- руководитель проекта;
- системный аналитик;
- frontend-разработчик;
- backend-разработчик;
- разработчик базы данных;
- тестировщик;
- DevOps-инженер.

Для каждого участника укажите:

1. Роль в команде.
2. Основные обязанности.
3. Задачи, за которые он отвечает.
4. Результат его работы.

Состав команды должен соответствовать выбранной архитектуре.

---

### Задание 6. Организация доски задач

Создайте доску задач для выбранного проекта с использованием Kanban или аналогичного инструмента.

Можно использовать Trello, Jira, YouTrack, GitHub Projects или собственную таблицу.

Доска должна содержать следующие этапы:

| Этап | Описание |
|---|---|
| **Backlog** | все запланированные задачи |
| **To Do** | задачи, готовые к выполнению |
| **In Progress** | задачи в работе |
| **Code Review** | задачи на проверке |
| **Testing** | задачи на тестировании |
| **Done** | завершенные задачи |

Сформируйте не менее 20 задач для разработки проекта.
