# Лабораторная работа № 1 по спецификации Чернобровенко Александра. Качество ПО на примере «Змейки»

Цель работы — оценить сложность, корректность, надёжность и трудоёмкость небольшого проекта. Для измерений используется игра «Змейка» на Python и Pygame. [Задание из ветки main](https://github.com/d26dodenko/PV-232/blob/bb38d87/Specification/Laba-1.md)

## Часть 1. Три проблемы разработки сложных систем

| Проблема | Возможное решение | Инструменты и методы |

## Часть 2. Игровой проект

Поле состоит из 20 × 16 клеток. В начале змейка занимает три клетки и движется вправо. Каждые 140 мс она проходит одну клетку. За еду начисляется одно очко и длина увеличивается на единицу. Удар о стену или собственное тело завершает партию. Заполнение всего поля означает победу.

| Управление | Действие |
| --- | --- |
| Стрелки | Поворот. Разворот на 180° запрещён. До следующего хода учитывается только первый поворот. |
| R | Новая партия после поражения или победы. |
| Esc или закрытие окна | Выход из игры. |

### Установка и запуск

Из корня репозитория выполните команды в терминале macOS или Linux.

```sh
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m snake
```

| Файл | Ответственность |
| --- | --- |
| `snake/body.py` | Класс `Snake` хранит сегменты, принимает поворот и перемещает тело. `Direction` задаёт направления. |

| `snake/app.py` | Класс `PygameApp` переводит нажатия клавиш и события таймера в команды модели, рисует поле и счёт. |

| `tests/test_game.py`, `tests/test_app.py` | Проверяют игровую модель и интерфейс соответственно. |

Для учёта задач используется Org mode. Каждая из четырёх задач содержит идентификатор, состояние, критерий приёмки и ссылку на результат. Трекер хранится в репозитории и открывается как текстовый файл. [Задачи проекта](tasks.org)

```sh

```

**Игровые правила.** 12 тестовых случаев проверяют обычный ход, рост, повторное размещение еды, ограничения размеров поля, нажатие двух стрелок до следующего хода и все четыре стены. На поле 4 × 2 воспроизводятся вход в уходящий хвост, удар о занятый сегмент и сбор последней еды. После поражения и победы следующие тики сохраняют состояние. Новая партия сбрасывает счёт.

### Расчёт сложности

За один ход `SnakeGame.step` проверяет состояние партии и координаты головы, передвигает змейку и обрабатывает еду. В методе четыре оператора `if`. Операции `and` в проверке координат и `or` в проверке столкновения добавляют ещё две точки принятия решения из-за сокращённого вычисления. По методу Маккейба базовый путь даёт единицу, поэтому **V(G) = 1 + 4 + 2 = 7**. Команда `radon cc -s snake/game.py` подтверждает результат `SnakeGame.step - B (7)`.

### Время реакции и дефектность

Время реакции измеряется от отправки стрелки вверх сразу после первого кадра до завершения отрисовки кадра, на котором голова уже сменила направление. Пять отдельных запусков на macOS arm64 с драйвером SDL `dummy` дали 143,7 / 144,6 / 142,9 / 141,6 / 142,7 мс. Медиана — **142,9 мс** при периоде движения 140 мс. Измерение включает ожидание следующего хода и обработку события. Команда для повторения одного измерения приведена ниже.


В трекере зарегистрировано 0 подтверждённых дефектов игры. Все 20 автоматических проверок прошли.
