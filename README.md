## 1. Анализ исходного модуля

Объект тестирования: функция `calculate_tastiness` (очень вкусный человек) из модуля `tasty_person.py`.

Функция рассчитывает условный индекс "вкусности" человека по пяти входным параметрам. Функция шуточная и отсылает к альбому "Четыре позиции Бруно", но оформлена по всем правилам тестирования.

| Параметр | Назначение | Допустимые значения | Недопустимые значения |
| --- | --- | --- | --- |
| `height_cm: float` | Рост в сантиметрах | Число от `50` до `250` включительно | Число `< 50` или `> 250` |
| `weight_kg: float` | Вес в килограммах | Число от `1` до `400` включительно | Число `< 1` или `> 400` |
| `fat_percent: float` | Процент жира в организме | Число от `0` до `70` включительно | Число `< 0` или `> 70` |
| `name: str` | Имя человека | Непустая строка | Пустая строка или не строка |
| `lifestyle: str` | Образ жизни | `"active"` или `"passive"` | Любое другое значение |
| Результат `float` | Итоговый индекс вкусности | Неотрицательное число от `0.0` до `100.0` | При некорректных входных данных вместо результата выбрасывается `ValueError` |

Бизнес-правила:

1. Если `height_cm < 50` или `height_cm > 250`, выбрасывается `ValueError("height_cm must be in range 50..250")`.
2. Если `weight_kg < 1` или `weight_kg > 400`, выбрасывается `ValueError("weight_kg must be in range 1..400")`.
3. Если `fat_percent < 0` или `fat_percent > 70`, выбрасывается `ValueError("fat_percent must be in range 0..70")`.
4. Если `name` пустая строка или не строка, выбрасывается `ValueError("name must be a non-empty string")`.
5. Если `lifestyle` не равен `"active"` или `"passive"`, выбрасывается `ValueError("lifestyle must be 'active' or 'passive'")`.
6. Базовый индекс рассчитывается как `weight_kg / (height_cm / 100) ** 2` (условный ИМТ).
7. Нормированный ИМТ считается мягко, без резких порогов: `norm_bmi = 100 / (1 + abs(bmi - 22) / 10)`.
8. Жир влияет через множитель: `fat_factor = 1 - fat_percent / 100` (0% дает 1.0, 70% дает 0.3).
9. Образ жизни влияет через множитель: `active` дает 1.2, `passive` дает 0.8.
10. Итог равен `norm_bmi * fat_factor * lifestyle_factor`.
11. Итог ограничивается диапазоном `[0.0, 100.0]`.

Классы эквивалентности:

| Параметр | Классы |
| --- | --- |
| `height_cm` | меньше `50`; `50..100`; `100..200`; `200..250`; больше `250` |
| `weight_kg` | меньше `1`; `1..50`; `50..150`; `150..400`; больше `400` |
| `fat_percent` | меньше `0`; `0..20`; `20..40`; `40..70`; больше `70` |
| `name` | корректная непустая строка; пустая строка; не строка |
| `lifestyle` | `"active"`; `"passive"`; недопустимое значение |

Граничные значения:

- для роста: `49.99`, `50`, `100`, `200`, `250`, `250.01`;
- для веса: `0.99`, `1`, `50`, `150`, `400`, `400.01`;
- для процента жира: `-0.01`, `0`, `20`, `40`, `70`, `70.01`;
- для имени: `""`, `"A"`, `"Илья"`;
- для образа жизни: `"active"`, `"passive"`, `"mixed"`.

## 4. Покрытые ветви кода

Тесты покрывают следующие ветви функции:

| Условие | Покрытая ветка `True` | Покрытая ветка `False` |
| --- | --- | --- |
| `height_cm` не число или `< 50` | TC-12 | TC-01 - TC-11, TC-13 - TC-19 |
| `height_cm > 250` | TC-13 | TC-01 - TC-12, TC-14 - TC-19 |
| `weight_kg` не число или `< 1` | TC-14 | TC-01 - TC-13, TC-15 - TC-19 |
| `weight_kg > 400` | TC-15 | TC-01 - TC-14, TC-16 - TC-19 |
| `fat_percent` не число или `< 0` | TC-16 | TC-01 - TC-15, TC-17 - TC-19 |
| `fat_percent > 70` | TC-17 | TC-01 - TC-16, TC-18, TC-19 |
| `name` пустое или не строка | TC-18 | TC-01 - TC-17, TC-19 |
| `lifestyle` недопустимый | TC-19 | TC-01 - TC-18 |
| `bmi < 22` (нормировка растет) | TC-04, TC-08 | TC-01 - TC-03, TC-05 - TC-07, TC-09 - TC-11 |
| `bmi > 22` (нормировка падает) | TC-01 - TC-03, TC-05 - TC-07, TC-09 - TC-11 | TC-04, TC-08 |
| `lifestyle == "active"` | TC-01, TC-03, TC-10 | TC-02, TC-04 - TC-09, TC-11 - TC-19 |
| `lifestyle == "passive"` | TC-02, TC-04 - TC-09, TC-11 - TC-19 | TC-01, TC-03, TC-10 |
| ограничение `max(0.0, ...)` | не срабатывает (значения всегда положительные) | TC-01 - TC-11 |
| ограничение `min(100.0, ...)` | TC-10 | TC-01 - TC-09, TC-11 |

Таким образом, проверены:

- позитивные сценарии для мягкой нормировки ИМТ (около идеального значения 22);
- негативные сценарии для всех пяти параметров;
- граничные значения роста (50 и 250), веса (1 и 400) и процента жира (0 и 70);
- ветви нормировки ИМТ как ниже, так и выше точки 22;
- влияние образа жизни (`active` и `passive`);
- влияние процента жира;
- верхнее ограничение результата (`min(100.0, ...)`).

Нижнее ограничение (`max(0.0, ...)`) при текущей формуле не срабатывает никогда, так как все множители положительные. Этот риск отмечен в выводах.

## 5. Вывод

Тестирование связывает требования с фактическим поведением программы. В этой лабораторной работе тесты показали, что функция `calculate_tastiness` корректно обрабатывает все входные диапазоны, граничные значения роста, веса и процента жира, а также влияние образа жизни и ошибки входных данных.

Формула была переосмыслена: вместо резких порогов и сложения/вычитания используются умножение и деление. Это дало мягкую нормировку ИМТ и позволило избежать частого попадания результата в крайние значения 0 и 100. Идеальный вариант (180 см, 40% жира, активный образ жизни) дает около 69, что соответствует ожидаемому "неплохому человеку".

В жизненном цикле ПО такие автотесты важны потому, что они помогают быстро находить регрессии после изменений кода, подтверждают выполнение бизнес-правил и повышают доверие к качеству программы. Запуск тестов в CI делает эту проверку автоматической: ошибка обнаруживается сразу после `push`, а не при ручной проверке.

При этом тесты не заменяют требования и проектирование. В данной работе остался непокрытым риск, связанный с нижним ограничением результата (`max(0.0, ...)`): при текущей формуле оно не срабатывает никогда, так как все множители положительные. Чтобы закрыть этот риск, можно либо убрать это ограничение как избыточное, либо добавить тест с такими данными, где результат теоретически мог бы уйти в минус.
