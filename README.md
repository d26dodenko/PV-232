## 1. Анализ исходного модуля

Объект тестирования: функция `calculate_parking_cost` из модуля `parking.py`.

Функция рассчитывает стоимость парковки по двум входным параметрам:

| Параметр | Назначение | Допустимые значения | Недопустимые значения |
| --- | --- | --- | --- |
| `hours: float` | Время парковки в часах | Число от `0` до `24` включительно | Число `< 0` или `> 24` |
| `is_resident: bool` | Признак резидента | `True`, `False` | Другие значения в задании не описаны |
| Результат `float` | Итоговая стоимость парковки | Неотрицательное число, не больше `600.0` | При некорректных входных данных вместо результата выбрасывается `ValueError` |

Бизнес-правила:

1. Если `hours < 0`, выбрасывается `ValueError("hours must be >= 0")`.
2. Если `hours > 24`, выбрасывается `ValueError("hours must be <= 24")`.
3. Если `hours <= 0.5`, парковка бесплатна и стоит `0.0`.
4. Если `0.5 < hours <= 3`, парковка стоит `150.0`.
5. Если `hours > 3`, парковка стоит `150.0 + (hours - 3) * 50.0`.
6. Стоимость до скидки не может превышать `600.0` (суточный максимум).
7. Если `is_resident=True`, применяется скидка 30% на рассчитанную стоимость парковки.
8. Если парковка бесплатна, скидка резидента не меняет результат: итог остается `0.0`.

Классы эквивалентности:

| Параметр | Классы |
| --- | --- |
| `hours` | отрицательное время; `0..0.5`; больше `0.5` и до `3`; больше `3` и до `12` (стоимость меньше максимума); больше `12` и до `24` (действует суточный максимум); больше `24` |
| `is_resident` | обычный пользователь; резидент |

Граничные значения:

- для времени: `-0.01`, `0`, `0.49`, `0.5`, `0.51`, `2.99`, `3`, `3.01`, `11.99`, `12`, `12.01`, `24`, `24.01`;
- для статуса резидента: `False`, `True`.

## 5. Автоматический запуск тестов в CI

Для автоматической проверки при каждом `push` настроен GitHub Actions workflow `.github/workflows/run_tests.yml`. Зависимости устанавливаются через `pip` из файла `requirements.txt`, версия Python берется из файла `.python-version`.

```yaml
name: Run Tests

on:
  push:

jobs:
  test:
    runs-on: ubuntu-latest

    steps:
      - name: Checkout repository
        uses: actions/checkout@v4

      - name: Set up Python
        uses: actions/setup-python@v5
        with:
          python-version-file: .python-version
          cache: pip

      - name: Install dependencies
        run: python -m pip install -r requirements.txt

      - name: Run tests
        run: python -m pytest tests/parking_tests.py -v
```

В `requirements.txt` обязательно должен быть указан `pytest`, а файл тестов должен называться `test_*.py`, иначе `pytest` не найдет тесты при запуске без указания пути.

## 6. Вывод

Тестирование связывает требования с фактическим поведением программы. В этой лабораторной работе тесты показали, что функция корректно обрабатывает все тарифы, граничные значения, суточный максимум, скидку резидента, бесплатную парковку и ошибки входных данных.

В жизненном цикле ПО такие автотесты важны потому, что они помогают быстро находить регрессии после изменений кода, подтверждают выполнение бизнес-правил и повышают доверие к качеству программы. Запуск тестов в CI делает эту проверку автоматической: ошибка обнаруживается сразу после `push`, а не при ручной проверке. При этом тесты не заменяют требования и проектирование: если важное поведение не описано в задании, его нужно отдельно уточнять и только потом покрывать проверками.
